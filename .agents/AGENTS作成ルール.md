# AGENTS 作成ルール

AGENTS.md や、その補助資料を作成・更新するときのルールです。

## 目的

AGENTS の指示が長くなりすぎて、実装に必要な情報が埋もれたり、エージェントの思考負荷が増えたりしないようにする。

## 作成方針

- 内容は簡潔にし、実装判断に直接必要なルールだけを書く。
- 同じ指示や、一般的すぎる説明を繰り返さない。
- 「必須」「原則」「参考」を区別し、重要度の低い内容を増やしすぎない。
- プロジェクト固有の仕様と、一般的な知識・SDK仕様を分離する。
- 詳細な説明、例、背景、API一覧は別文書へ分け、AGENTS からは短く参照する。
- 一つの項目に複数のルールを詰め込まず、短い箇条書きにする。
- 現在のリポジトリや使用ツールで確認できない推測を、規則として追加しない。
- 古くなった指示、重複した指示、実装と矛盾する指示は削除または更新する。

## まとめる内容

優先して書くのは次の項目です。

- プロジェクトの目的と構成
- ビルド・テスト方法
- 重要な設計上の不変条件
- 命名・実装・変更範囲のルール
- 禁止事項
- 作業完了時の確認事項

## 作成後の確認

- 同じ内容が既存の AGENTS や補助文書にないか確認する。
- 参照先のファイルが存在し、リンクやパスが正しいことを確認する。
- 実装者が作業中にすぐ判断できる長さか確認する。
- 変更対象と無関係な説明を削る。
- 文章を追加する前に、既存の項目を統合・短縮できないか検討する。
