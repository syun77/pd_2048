# ツール作成ルール

特に指定がない限り、編集ツールは Python + Tkinter で作成する。基本的には単一ファイルにまとめ、機能追加時も過度に分割しない。

## 基本方針

- 既存の操作感とファイル形式を優先し、要求範囲外の機能や依存関係を増やさない。
- UI、編集状態、ファイル入出力を同じファイル内で責務ごとに整理する。
- 起動方法、保存先、エラー内容が利用者に分かるようにする。
- 外部ライブラリは必要性が明確な場合だけ追加する。

## グリッド編集

- グリッド上にタイルを配置する場合、左クリックで配置する。
- 左ボタンを押したままドラッグすると、通過したセルへ連続して配置する。
- 右クリック、または指定された消去操作でタイルを消去できるようにする。
- グリッド座標とキャンバス座標の変換を一箇所に集約する。
- 範囲外のセル、不正な値、中央固定セルなど編集できない領域を明確に扱う。
- 変更後は必要な範囲だけ再描画し、編集中の状態を画面上で確認できるようにする。

## ファイル操作

- Cmd+S で保存する。既存ファイルを開いている場合は上書き保存する。
- Cmd+O でファイル選択ダイアログを開く。
- 起動時は、最後に開いたファイルが存在すれば自動で開く。
- 最後に開いたファイルの情報は、ツール本体のデータと混同しない設定ファイルへ保存する。
- 指示がなければ JSON を使用し、UTF-8 で読み書きする。
- 保存前に必要な形式・必須項目・値の範囲を検証する。
- 開く・保存・JSON解析に失敗した場合は、データを壊さず、原因をダイアログで知らせる。
- 上書き保存では一時ファイルへの保存後に置き換えるなど、途中失敗で元ファイルを失わない方法を検討する。

## Undo / Redo

- Cmd+Z は UNDO、Cmd+Shift+Z は REDO とする。
- 編集操作単位で履歴を記録し、ドラッグ配置は一連の操作として扱う。
- 新しい編集を行ったら REDO 履歴を破棄する。
- ファイルを開く、初期化する、保存状態を切り替えるときは履歴を適切にリセットする。
- Undo/Redo 後は表示、選択状態、未保存状態を同期する。
- 履歴には必要なデータだけを保持し、無制限に増やさない。

## エディタに必要な基本機能

- 新規作成、開く、保存、名前を付けて保存、終了をメニューから実行できる。
- 未保存の変更がある場合、開く・新規作成・終了の前に保存確認を表示する。
- 編集中のファイル名と未保存状態をタイトルバーまたはステータスに表示する。
- 現在のセル、選択中のタイル、操作結果をステータスへ表示する。
- 必要に応じて拡大・縮小、表示更新、グリッド表示切り替えを用意する。
- キーボード操作だけでも主要機能へ到達できるよう、メニューにショートカットを表示する。
- macOS の Cmd を基本表記とし、Windows/Linux では同等の Ctrl 操作も可能にする。
- ウィンドウサイズや最後の表示設定を、必要な場合だけ設定として復元する。

## 実装・検証

- データモデルと描画を分離し、描画処理から保存データを直接書き換えない。
- 同じ座標変換、検証、履歴登録を複数箇所へ複製しない。
- ファイルを開いた直後、編集直後、Undo/Redo 後、保存後に未保存状態が正しく更新されることを確認する。
- 空データ、不正 JSON、欠損項目、範囲外の値、存在しないファイルを確認する。
- 左クリック、左ドラッグ、消去、Cmd+S、Cmd+O、Cmd+Z、Cmd+Shift+Z、終了時の保存確認を確認する。
- 例外を握りつぶさず、利用者向けのエラーと開発者向けのログを必要に応じて分ける。
