# 実績エディター仕様書

## 1. 目的

`仕様書/achievement_editor.py` は、ゲーム内 ACHIEVEMENTS 画面で使用する実績定義JSONを作成・編集するためのデスクトップツールである。

- Python 3 と Tkinter で動作する。
- 実行方法は `python3 achievement_editor.py`。
- 起動時、前回開いたJSONが存在する場合は自動的に開く。
- 保存形式はJSONで、実績定義の配列を `achievements` キーに格納する。
- 実績の達成状態はこのJSONには保存しない。プレイヤーごとの達成状態はゲーム側の `datastore` に別管理する。

## 2. 画面構成

左側に実績一覧、右側に選択中の実績フォームを表示する。

### 2.1 メニュー

| メニュー | 項目 | 動作 |
|---|---|---|
| File | New | 新規実績ファイルを作成する |
| File | Open... | JSONを開く |
| File | Save | 現在のファイルへ保存する。未保存の場合は Save As を開く |
| File | Save As... | 保存先とファイル名を指定して保存する |
| File | Exit | 終了する。未保存変更がある場合は確認する |

キーボードショートカットは、新規作成が `Ctrl/Cmd-N`、開くが `Ctrl/Cmd-O`、保存が `Ctrl/Cmd-S` である。

未保存変更がある場合、ウィンドウタイトルは `achievements.json* - 2048 Achievement Editor` のようにファイル名の直後へ `*` を表示する。

### 2.2 一覧操作

| ボタン | 動作 |
|---|---|
| Add | 新規実績を追加する |
| Duplicate | 選択中の実績を複製する |
| Delete | 選択中の実績を削除する |
| Renumber | 現在の並び順に合わせて `no` を 1 から振り直す |
| Up / Down | 選択中の実績を上下へ移動する |

実績は最低1件必要である。

## 3. 実績項目

| 項目 | JSONキー | 内容 |
|---|---|---|
| NO | `no` | 表示用の実績番号。正の整数 |
| ID | `id` | 保存・判定用の内部ID。小文字英数字と `_` |
| Category | `category` | `SYSTEM`、`NORMAL`、`TIME_ATTACK`、`CORE_RUSH`、`PRACTICE` |
| Name JA / EN | `name.ja`, `name.en` | 実績名。どちらか一方は必須 |
| Description JA / EN | `description.ja`, `description.en` | 達成条件の説明文 |
| Condition Type | `condition.type` | 判定種別 |
| Scope | `condition.scope` | `RUN` または `LIFETIME` |
| Operator | `condition.operator` | `>=`、`==`、`<=`、`>`、`<` |
| Params | `condition.params` | 判定パラメータ。エディターでは `key=value,key=value` 形式で入力する |
| Reward Type | `reward.type` | `NONE`、`BGM_UNLOCK`、`THEME_UNLOCK`、`TITLE_BADGE`、`SOUND_UNLOCK` |
| Reward ID | `reward.id` | 解放する報酬の内部ID |
| Hidden until unlocked | `hidden` | 未達成時に内容を隠すか |
| Show progress | `progressVisible` | 未達成時に進捗を表示するか |

`Reward Type` が `NONE` 以外の場合、`Reward ID` は必須である。

## 4. Condition Type

| 値 | 想定条件 | Params例 |
|---|---|---|
| `MERGE_COUNT` | マージ回数 | `count=1` |
| `TILE_VALUE` | 指定値以上のブロック作成 | `value=2048` |
| `SCORE` | 1プレイ中のスコア | `score=10000` |
| `COMBO` | 最大コンボ数 | `combo=3` |
| `CLEAR_MODE` | 指定モードのクリア | `mode=NORMAL` |
| `PRACTICE_CLEAR_COUNT` | PRACTICEクリア数 | `count=10` |
| `NO_REWIND_CLEAR` | REWINDなしクリア | `mode=NORMAL` |
| `PLAY_COUNT` | プレイ回数 | `count=10` |
| `TOTAL_SCORE` | 累計スコア | `score=100000` |
| `BEST_TIME_MS` | ベストタイム | `mode=TIME_ATTACK,target=64,timeMs=60000` |

`Scope` が `RUN` の条件は1プレイ内で判定する。`LIFETIME` の条件は累計統計や保存済み記録から判定する。

## 5. JSON出力例

```json
{
  "achievements": [
    {
      "no": 1,
      "id": "first_merge",
      "category": "SYSTEM",
      "name": {
        "ja": "はじめての合体",
        "en": "First Merge"
      },
      "description": {
        "ja": "はじめてブロックを合体させる。",
        "en": "Merge blocks for the first time."
      },
      "condition": {
        "type": "MERGE_COUNT",
        "scope": "LIFETIME",
        "operator": ">=",
        "params": {
          "count": 1
        }
      },
      "reward": {
        "type": "NONE",
        "id": ""
      },
      "hidden": false,
      "progressVisible": true
    }
  ]
}
```

## 6. 入力値の検証

保存時と `Validate` 実行時に次を検証する。

- 実績が1件以上あること。
- `no` が正の整数であり、重複しないこと。
- `id` が `^[a-z][a-z0-9_]*$` に一致し、重複しないこと。
- `category`、`condition.type`、`condition.scope`、`condition.operator`、`reward.type` が定義済み候補であること。
- 実績名は日本語・英語のどちらか一方が空でないこと。
- `condition.params` がオブジェクトとして解釈できること。
- `reward.type` が `NONE` 以外の場合は `reward.id` が空でないこと。

既存JSONを開く場合は、`achievements` 配列を持つオブジェクト、または実績定義の配列そのものを読み込める。

## 7. ファイル操作と設定

- ファイル選択ダイアログの初期フォルダは、最後に読み込んだファイルが存在する場合はその親フォルダを使用する。
- 最後に読み込んだファイルが存在しない場合は、`achievement_editor.py` と同じフォルダを使用する。
- 最後に開いたファイルのパスは `仕様書/.achievement_editor_settings.json` に保存する。
- 設定ファイルが破損している、または記録されたファイルが存在しない場合は無視し、新規実績で起動する。
