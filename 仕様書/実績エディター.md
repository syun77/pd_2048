# 実績エディター仕様書

## 1. 目的

`仕様書/achievement_editor.py` は、ゲーム内 ACHIEVEMENTS 画面で使用する実績定義JSONを作成・編集するためのデスクトップツールである。

- Python 3 と Tkinter で動作する。
- 実行方法は `python3 achievement_editor.py`。
- 起動時、前回開いたJSONが存在する場合は自動的に開く。
- 保存形式はJSONで、実績定義の配列を `achievements` キーに格納する。
- ゲームで使用する実績定義の正本は `pd_2048/source/assets/achievement/achievements.json` とする。
- 実績の達成状態はこのJSONには保存しない。プレイヤーごとの達成状態はゲーム側の `datastore` に別管理する。

## 2. 画面構成

左側に実績一覧、右側に選択中の実績フォームを表示する。

### 2.1 メニュー

| メニュー | 項目 | 動作 |
|---|---|---|
| File | New | 新規実績ファイルを作成する |
| File | Open... | JSONを開く |
| File | Save | 現在のファイルへ保存する。未保存の場合は Save As を開く |
| File | Save As... | 保存先とファイル名を指定して保存する |
| File | Exit | 終了する。未保存変更がある場合は確認する |
| Tools | Edit Definitions... | Category、Condition Type、Scope、Reward Type の候補定義を編集する |

キーボードショートカットは、新規作成が `Ctrl/Cmd-N`、開くが `Ctrl/Cmd-O`、保存が `Ctrl/Cmd-S` である。

未保存変更がある場合、ウィンドウタイトルは `achievements.json* - 2048 Achievement Editor` のようにファイル名の直後へ `*` を表示する。

### 2.2 一覧操作

| ボタン | 動作 |
|---|---|
| Add | 新規実績を追加する |
| Duplicate | 選択中の実績を複製する |
| Delete | 選択中の実績を削除する |
| Up / Down | 選択中の実績を上下へ移動する |

実績は最低1件必要である。
実績の表示順は `achievements` 配列の順番とし、一覧の表示番号は配列順に 1 から自動採番する。表示番号はJSONに保存しない。

### 2.3 定義編集

`Tools > Edit Definitions...` から、実績フォームで選択する次の候補を編集できる。

- Category
- Condition Type
- Scope
- Reward Type

各候補は Lua やJSONから参照する `Internal Name` と、エディター上に表示する `Display Name` を持つ。

| ボタン | 動作 |
|---|---|
| Add | 新しい候補を追加して選択する |
| Delete | 選択中の候補を削除する |
| OK | 定義を反映する |
| Cancel | 変更を破棄する |

選択中の候補は、`Internal Name` または `Display Name` を編集した時点で定義編集ダイアログ内の一時データへ保持される。親画面へ反映されるのは `OK` を押した場合だけで、`Cancel` を押した場合は定義編集ダイアログ内の変更を破棄する。

`Internal Name` は `^[A-Z][A-Z0-9_]*$` に一致する必要がある。削除や名称変更によって既存実績が参照する候補がなくなる場合、その定義変更は反映できない。

## 3. 実績項目

| 項目 | JSONキー | 内容 |
|---|---|---|
| ID | `id` | 保存・判定用の内部ID。小文字英数字と `_` |
| Category | `category` | 定義編集画面で設定した Category の内部名 |
| Name JA / EN | `name.ja`, `name.en` | 実績名。どちらか一方は必須 |
| Description JA / EN | `description.ja`, `description.en` | 達成条件の説明文 |
| Condition Type | `condition.type` | 定義編集画面で設定した Condition Type の内部名 |
| Scope | `condition.scope` | 定義編集画面で設定した Scope の内部名 |
| Operator | `condition.operator` | `>=`、`==`、`<=`、`>`、`<` |
| Params | `condition.params` | 判定パラメータ。エディターでは `key=value,key=value` 形式で入力する |
| Reward Type | `reward.type` | 定義編集画面で設定した Reward Type の内部名 |
| Reward ID | `reward.id` | 解放する報酬の内部ID |
| Hidden until unlocked | `hidden` | 未達成時に内容を隠すか |
| Show progress | `progressVisible` | 未達成時に進捗を表示するか |

`Reward Type` が `NONE` 以外の場合、`Reward ID` は必須である。

## 4. 定義候補

### 4.1 Category

| 値 | 対象 |
|---|---|
| `SYSTEM` | ゲーム全体に関する実績 |
| `NORMAL` | NORMAL固有の実績 |
| `TIME_ATTACK` | TIME ATTACK固有の実績 |
| `CORE_RUSH` | CORE RUSH固有の実績 |
| `PRACTICE` | PRACTICE固有の実績 |
| `MAIN_GAME` | PRACTICE以外の通常プレイに共通する実績 |

### 4.2 Condition Type

| 値 | 想定条件 | Params例 |
|---|---|---|
| `MERGE_COUNT` | マージ回数 | `count=1` |
| `TILE_VALUE` | 指定値以上のブロック作成 | `value=2048` |
| `SCORE` | 1プレイ中のスコア | `score=10000` |
| `COMBO` | 最大コンボ数 | `value=3` |
| `LEVEL` | NORMALの1プレイ中の到達レベル | `value=10` |
| `CLEAR_MODE` | 指定モードのクリア | `mode=NORMAL` |
| `PRACTICE_CLEAR_COUNT` | PRACTICEクリア数。`all=true` は全ステージクリア | `all=true` |
| `NO_REWIND_CLEAR` | REWINDなしクリア | `mode=NORMAL` |
| `PLAY_COUNT` | プレイ回数 | `count=10` |
| `TOTAL_SCORE` | 累計スコア | `score=100000` |
| `CLEAR_TIME_MINUTE` | 対象モードを指定分以内にクリア | `value=2` |
| `UNLOCK_ACHIEVEMENT` | 達成済み実績数 | `value=5` |

`Scope` が `RUN` の条件は1プレイ内で判定する。`LIFETIME` の条件は累計統計や保存済み記録から判定する。

`UNLOCK_ACHIEVEMENT` の達成済み数には、判定中の実績自身を含めない。他の `UNLOCK_ACHIEVEMENT` 実績は達成済みであれば数に含める。実績解除によって別の達成数条件を満たす可能性があるため、新たに解除される実績がなくなるまで達成数条件を再評価する。

### 4.3 Reward Type

| 値 | 内容 | 現行Reward ID |
|---|---|---|
| `NONE` | 報酬なし | 空文字 |
| `SOUND_UNLOCK` | サウンドテストを解放 | `soundtest` |
| `TIMEATTACK_UNLOCK` | TIME ATTACKまたはCORE RUSHの対象モードを解放 | `sprint64`、`sprint256`、`sprint512`、`corerush2048` |
| `REPLAY_UNLOCK` | リプレイ機能を解放 | `replay` |
| `EXTEND_PLAY` | リプレイデータの続きからプレイする機能を解放 | `extend` |

```json
{
  "definitions": {
    "categories": [
      {"id": "SYSTEM", "label": "System"},
      {"id": "NORMAL", "label": "Normal"}
    ],
    "conditionTypes": [
      {"id": "TILE_VALUE", "label": "生成したタイルの値"}
    ],
    "scopes": [
      {"id": "RUN", "label": "Run"},
      {"id": "LIFETIME", "label": "Lifetime"}
    ],
    "rewardTypes": [
      {"id": "TIMEATTACK_UNLOCK", "label": "タイムアタックモードの開放"}
    ]
  },
  "achievements": [
    {
      "id": "tile64",
      "category": "NORMAL",
      "name": {
        "ja": "64タイルの作成",
        "en": "Created a 64 Tile"
      },
      "description": {
        "ja": "ノーマルモードで64タイルを作成した",
        "en": "Created a 64 tile in Normal Mode."
      },
      "condition": {

        "scope": "RUN",

      "progressVisible": false
    }

```

## 7. 入力値の検証

保存時と `Validate` 実行時に次を検証する。

- 実績が1件以上あること。
- `id` が `^[a-z][a-z0-9_]*$` に一致し、重複しないこと。
- 定義候補の内部名が `^[A-Z][A-Z0-9_]*$` に一致し、同じ種別内で重複しないこと。
- `category`、`condition.type`、`condition.scope`、`condition.operator`、`reward.type` が定義済み候補であること。
- 実績名は日本語・英語のどちらか一方が空でないこと。
- `condition.params` がオブジェクトとして解釈できること。
- `reward.type` が `NONE` 以外の場合は `reward.id` が空でないこと。

既存JSONを開く場合は、`achievements` 配列を持つオブジェクト、または実績定義の配列そのものを読み込める。`definitions` がない既存JSONは既定の候補定義を補完する。旧形式の `no` は読み込み時に無視し、保存時には出力しない。

## 8. ファイル操作と設定

- ファイル選択ダイアログの初期フォルダは、最後に読み込んだファイルが存在する場合はその親フォルダを使用する。
- 最後に読み込んだファイルが存在しない場合は、`achievement_editor.py` と同じフォルダを使用する。
- 最後に開いたファイルのパスは `仕様書/.achievement_editor_settings.json` に保存する。
- 設定ファイルが破損している、または記録されたファイルが存在しない場合は無視し、新規実績で起動する。
