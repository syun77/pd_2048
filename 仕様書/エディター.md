# PRACTICE ステージエディター仕様書

## 1. 目的

`仕様書/editor.py` は、Playdate版2048の PRACTICE モードで使用するステージJSONを作成・編集するためのデスクトップツールである。

- Python 3 と Tkinter で動作する。
- 実行方法は `python3 editor.py`。
- 有効なステージJSONを `editor.py` または実行中のエディターウィンドウへドラッグ＆ドロップすると、そのファイルを開く。
- ステージJSONは、通常 `pd_2048/source/assets/practice/` に保存する。
- 保存したJSONは、Playdate側の `PracticeStageLoader` が連番ファイルとして読み込む。

本ツールのプレビューは、ステージ確認を目的とした簡易プレイ環境であり、Playdate本体の画面表示・アニメーション・一部のゲームモード機能を再現しない。

## 2. 画面構成

### 2.1 メニュー

| メニュー | 項目 | 動作 |
|---|---|---|
| File | New | 新規ステージを作成する |
| File | Open... | JSONステージを開く |
| File | Save | 現在のファイルへ保存する。未保存の場合は Save As を開く |
| File | Save As... | 保存先とファイル名を指定して保存する |
| File | Exit | 終了する。未保存変更がある場合は確認する |
| Edit | Undo | 直前の編集を取り消す |
| Edit | Redo | 取り消した編集をやり直す |

キーボードショートカットは、保存が `Ctrl/Cmd-S`、UNDO が `Ctrl/Cmd-Z`、REDO が `Ctrl/Cmd-Shift-Z` である。

### 2.2 Initial Board

5×5の盤面を表示する。盤面の論理座標は左上を `(1,1)`、右下を `(5,5)` とする。

- 左クリック：選択中の値のブロックを配置する。
- 右クリック：ブロックを削除する。
- `Block` コンボボックス：配置する値を選択する。
- 配置可能な値は `2, 4, 8, ... 2048` の2の累乗である。
- 中央セル `(3,3)` は回転軸のため、配置できない。

既存セルを左クリックすると、そのセルの値を選択値で置き換える。中央セルや盤面外への操作は無視され、中央セル操作時はステータス欄に理由を表示する。

### 2.3 ステージ設定

| 項目 | 内容 |
|---|---|
| Label | ステージ表示名。空欄不可 |
| NEXT mode | `LOOP`、`FIXED` または `RANDOM` |
| Fixed NEXT (1-10) | 固定NEXT値を10個入力する |
| Random values | RANDOM時の候補値。カンマ区切り |
| Random weights | RANDOM時の重み。カンマ区切り |
| Clear Objective / Mode | `ANY` または `ALL` |
| Clear Objective / Type | `TILE_VALUE`、`COMBO`、`SCORE`、`MERGE_COUNT` |
| Clear Objective / Value | 目標値。1以上の整数 |

`NEXT mode` が `LOOP` の場合、固定NEXTを先頭から順番に使用し、末尾まで進むと先頭へ戻る。`FIXED` の場合、固定NEXTを先頭から順番に使用し、末尾まで到達すると終了する。`RANDOM` の場合、`Random values` と `Random weights` を重み付き抽選で使用する。

## 3. 新規ステージの初期値

`New` で作成されるステージは次の値を持つ。

```json
{
  "id": "001",
  "label": "NEW STAGE",
  "description": {"ja": "", "en": ""},
  "initialBoard": [],
  "nextValues": [2, 2, 2, 2, 2, 2, 2, 2, 2, 2],
  "nextPolicy": "LOOP",
  "nextRandom": {"values": [2, 4], "weights": [90, 10]},
  "objectiveMode": "ANY",
  "objectives": [{"type": "TILE_VALUE", "value": 64}],
  "turnLimit": 0
}
```

## 4. JSON出力仕様

### 4.1 ステージ本体

| キー | 型 | 内容 |
|---|---|---|
| `id` | 文字列 | ステージID。既存ファイルを保存する場合は元の値を維持する |
| `label` | 文字列 | ステージ名 |
| `description` | オブジェクト | 1行程度の説明文。`ja` に日本語、`en` に英語を保存する |
| `initialBoard` | 配列 | 初期配置ブロックの配列 |
| `nextValues` | 整数配列 | 固定NEXT値。エディターでは10個 |
| `nextPolicy` | 文字列 | `LOOP`、`FIXED` または `RANDOM` |
| `nextRandom` | オブジェクト | RANDOM時の候補値と重み |
| `objectiveMode` | 文字列 | `ANY` または `ALL` |
| `objectives` | 配列 | クリア目標。エディターは1件を出力する |
| `turnLimit` | 整数 | 手数制限。`0` は無制限 |

### 4.2 初期盤面

`initialBoard` の各要素は次の形式である。

```json
{"x": 2, "y": 3, "value": 8}
```

`x` と `y` は1〜5の論理座標、`value` は2の累乗のブロック値である。中央の `(3,3)` は使用できない。盤面上のブロックは、保存時に空セルを除いて配列化される。

### 4.3 NEXT設定

```json
"nextValues": [2, 2, 4, 8, 2, 2, 4, 8, 2, 2],
"nextPolicy": "LOOP",
"nextRandom": {
  "values": [2, 4],
  "weights": [90, 10]
}
```

`RANDOM` の場合、`values` と `weights` は同じ長さでなければならない。候補値は2の累乗、重みは0以上の整数とする。`LOOP` でも `nextRandom` はJSONに保存されるが、ゲーム中は使用しない。

### 4.4 クリア目標

```json
"objectiveMode": "ANY",
"objectives": [
  {"type": "TILE_VALUE", "value": 64}
]
```

プレビューで対応する目標判定は次のとおり。

| `type` | 達成条件 |
|---|---|
| `TILE_VALUE` | 盤面の最大ブロック値が目標値以上 |
| `COMBO` | 現在のコンボ数が目標値以上 |
| `SCORE` | スコアが目標値以上 |
| `MERGE_COUNT` | 累計マージ回数が目標値以上 |

`ANY` はいずれか、`ALL` はすべての目標を達成するとクリアになる。現行エディターUIは目標を1件だけ編集・出力するが、読み込んだ複数目標は先頭の目標だけを編集対象として表示する。

## 5. 入力値の検証

保存時とプレビュー起動時に同じ検証を行い、エラーがある場合は処理を中止してダイアログを表示する。

- `label` が空でないこと。
- `description` が文字列、または `ja` と `en` に文字列を持つオブジェクトであること。
- `nextValues` が10個であること。
- 初期盤面に中央セル `(3,3)` のブロックがないこと。
- 初期盤面のブロック値が `2, 4, 8, ... 2048` のいずれかであること。
- `RANDOM` の候補値が1個以上あること。
- `RANDOM` の候補値と重みの個数が一致すること。
- `RANDOM` の候補値が2の累乗であること。
- `RANDOM` の重みが負でないこと。
- 目標値が正であること。
- 手数制限が0以上であること。0は無制限とする。

JSONを開く際は、省略されたキーに対して次の既定値を補完してから検証する。

- `label`: ファイル名の拡張子を除いた名前
- `description`: `ja=""`, `en=""`
- `initialBoard`: `[]`
- `nextValues`: `[2]`を10個
- `nextPolicy`: `LOOP`
- `nextRandom`: `values=[2,4]`, `weights=[90,10]`
- `objectiveMode`: `ANY`
- `objectives`: `TILE_VALUE` の64
- `turnLimit`: `0`（無制限）

なお、JSONの構文、ファイル読み込み、検証に失敗した場合は、元のステージを変更せずに開く処理を終了する。

## 6. ファイル操作と設定

- ステージJSONを `editor.py` にドラッグ＆ドロップして起動した場合は、前回開いたファイルよりもドロップされたファイルを優先して開く。
- 実行中のエディターウィンドウへのドラッグ＆ドロップは、OSまたはTkがファイルドロップ通知に対応する環境で利用できる。未保存の変更がある場合は、通常のファイルを開く操作と同じ確認を表示する。
- 一度にドロップして開けるのは1ファイルだけである。読み込み時は `Open...` と同じJSON検証を行う。
- ファイルを開く・`Save As...` の初期フォルダは、最後に読み込んだJSONが存在する場合はその親フォルダとする。該当するJSONがない場合は `editor.py` と同じディレクトリを使用し、`Save As...` の初期ファイル名は `001.json`。
- JSONはUTF-8、インデント2個、末尾改行付きで保存する。
- 保存後はウィンドウタイトルから未保存マーク `*` を外す。
- 変更中のファイルはウィンドウタイトルのファイル名の後ろに `*` を付ける。
- 最後に開いたファイルのパスを、`仕様書/.practice_editor_settings.json` に保存する。
- 次回起動時、設定ファイルに記録されたファイルが存在すれば自動的に開く。
- 設定ファイルの破損や読み込み失敗は無視し、空の新規ステージで起動する。

`.practice_editor_settings.json` は作業用ファイルであり、PRACTICEステージの配布データではない。

未保存変更がある状態で新規作成・ファイルを開く・終了を実行すると、保存、破棄、キャンセルを選択する確認ダイアログを表示する。保存に失敗する変更が残っている場合、画面を閉じたり切り替えたりしない。

## 7. UNDO / REDO

編集操作の前に盤面とフォームのスナップショットを履歴へ保存する。

- 履歴の対象は盤面、ラベル、説明文、NEXT設定、RANDOM設定、目標設定、手数制限。
- UNDOで履歴を1つ戻し、現在状態をREDO履歴へ移す。
- REDOでREDO履歴を1つ進める。
- 新しい編集を行うとREDO履歴を破棄する。
- UNDO/REDO後は未保存状態になる。
- ファイルを新規作成・読み込みすると、両方の履歴を消去する。

## 8. プレビュー

`Preview / Check` は入力値を検証し、問題がなければ別ウィンドウで簡易プレイを開始する。

### 8.1 操作

| 入力 | 動作 |
|---|---|
| 左右キー | 落下列を移動。1〜5列に制限 |
| 下キー / Space | 現在ブロックを落とす |
| H | HOLD |
| R | 初期状態へリセット |

プレビュー開始時の落下列は中央列（3列目）である。現在ブロック1個とNEXTキュー4個を初期化し、NEXTには先頭3個を表示する。

### 8.2 プレビューのゲーム処理

プレビューは次の処理を実装する。

- 初期盤面の読み込み。
- `LOOP` または重み付き `RANDOM` によるNEXT生成。
- 通常仕様と同じ中央セルを除外した落下可能セルの探索。
- 同値の上下左右ブロックのマージ。
- マージによるスコア、コンボ、累計マージ回数の更新。
- 落下位置・マージ方向に基づく簡易評価と盤面90度回転。
- 回転後のアクティブブロックを起点とした追加マージ。
- HOLD、クリア目標、ゲームオーバー判定。
- 手数制限が1以上の場合、指定手数に達するとゲームオーバーになる。
- `FIXED` の場合、固定NEXTを使い切るとゲームオーバーになる。
- 操作イベントのログ表示。
- 説明文の確認表示。英語があれば英語、なければ日本語を表示する。

プレビューのスコア加算は、マージ後の値に100を掛け、コンボ増分ボーナスを加えた値である。ゲームオーバーは、いずれの列にも落下できなくなったときに表示する。クリア成立後またはゲームオーバー後はDROPとHOLDを受け付けない。

### 8.3 プレビューと本編の差異

- Playdateの入力、アニメーション、効果音、描画レイアウトは再現しない。
- Playdate本編の乱数系列ではなく、Pythonの `random.Random` を使う。`randomSeed` がJSONにあればその値、なければ1を使用する。
- プレビューのHOLDには、1手につき1回の使用制限がある。
- プレビューの回転後マージでは、回転評価値を追加更新しない。
- 画面上のイベントログと簡易ステータスを確認用に表示する。

## 9. Playdate側へ組み込む手順

1. エディターでステージを作成する。
2. `Save As...` で `pd_2048/source/assets/practice/NNN.json` として保存する。
3. `NNN` は数字だけの連番ファイル名にする。`PracticeStageLoader` はこの形式のJSONだけを読み込む。
4. JSONの `label` がPRACTICEメニューの表示名になり、`description` がゲーム画面の説明文になる。
5. `pdc pd_2048/source pd_2048/builds` でビルドし、Playdate Simulatorまたは実機でPRACTICEを確認する。

エディターはファイル名の連番、重複した座標、Playdate側で必要な追加条件までは管理しない。保存後は、実際のPRACTICEモードで読み込みと操作を確認すること。

## 10. 既知の制約

- `id` は新規作成時に `001` で固定され、Save As時にファイル名から自動採番しない。
- 初期盤面の同一座標の重複は、エディターの検証では明示的に拒否しない。盤面表示・保存時は後から処理した値が有効になる。
- `nextValues` の各値、座標範囲、`nextPolicy`、目標種別などは、検証関数が明示的に検査する範囲に限られる。Playdate側のローダー・ゲームコントローラでも追加検証される。
- RANDOM設定は `nextPolicy` が `RANDOM` のときだけプレビューと本編で使用される。
- エディター起動にはTkinterが必要で、Playdate本体上では動作しない。
