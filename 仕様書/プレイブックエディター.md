# PLAYBOOK・プレイブックエディター仕様書

## 1. 目的

PLAYBOOKは、基本操作、コンボ、高い数値のブロックを作る考え方を、画像付きの複数ページで説明する画面である。一部のヒントは実績報酬によって解放する。

`仕様書/playbook_editor.py`は、PLAYBOOK定義を作成・編集するPython 3＋Tkinter製のデスクトップツールとする。エディタで管理する正本は`pd_2048/source/assets/playbook/playbooks.json`とし、同じフォルダへ説明画像のPNGを配置する。

この文書はデータと画面の設計を定める。`playbook_editor.py`は本仕様に従って実装済みである。PLAYBOOKのゲーム内一覧・詳細表示と実績連動は別作業とする。

## 2. ゲーム内画面

### 2.1 PLAYBOOK一覧

- `playbooks.json`の`playbooks`配列順で、解放済みのヒントだけを表示する。
- `unlockNo=0`は最初から表示する。`unlockNo>=1`は対応するアンロック番号を取得済みの場合だけ表示する。
- 未解放の項目は`????`などの代替項目を出さず、一覧から隠す。
- 上下キーで選択し、Aボタンで選択中のヒントを1ページ目から開く。
- 項目数が5件を超える場合は、既存メニューと同じスクロール表示を使用する。
- 詳細から戻った場合は一覧の選択位置を保持する。タイトルから入り直した場合は先頭を選択する。
- Bボタンまたはシステムメニューの`Back to Title`でタイトルへ戻る。
- 読み込み可能なヒントがない場合は`NO PLAYBOOKS AVAILABLE`を表示し、Bボタンによる復帰だけを受け付ける。

### 2.2 ヒント詳細

- 画面上部にヒント名と`現在ページ/総ページ`を表示する。
- 画面中央の画像領域へ、ページの画像を原寸・中央揃えで表示する。画像の最大サイズは360×128pxとし、ゲーム側では拡大縮小しない。
- 画面下部の説明領域へ、選択言語の説明文を折り返して表示する。
- 左右キーで前後のページへ移動する。先頭で左、末尾で右を押しても循環しない。
- 移動可能な方向だけ、ページ番号の左右にページ切り替えカーソルを表示する。
- Bボタンまたはシステムメニューの`Back to Playbook`でPLAYBOOK一覧へ戻る。
- Aボタン、上下キー、クランクは使用しない。
- ページを開くたびに画像を読み直さず、現在のヒントで使用する画像だけを必要に応じてキャッシュする。別のヒントへ移動した時点で不要な画像参照を解放できる設計とする。

### 2.3 言語

- ヒント名と各ページの説明文は日本語・英語を持つ。
- 将来追加する共通言語設定を参照して表示を切り替える。
- 言語設定の実装前は、システム言語が日本語なら日本語、それ以外なら英語を優先する。
- 優先言語が空の場合はもう一方へフォールバックする。両方が空のデータは保存時の検証エラーとする。

## 3. JSON形式

### 3.1 ルート

```json
{
  "version": 1,
  "playbooks": []
}
```

| JSONキー | 型 | 内容 |
|---|---|---|
| `version` | integer | PLAYBOOK定義形式。初期値は`1` |
| `playbooks` | array | ヒント定義。配列順が一覧の表示順 |

### 3.2 ヒント

| JSONキー | 型 | 内容 |
|---|---|---|
| `id` | string | 保存・参照用の一意な内部ID。小文字英数字と`_` |
| `unlockNo` | integer | `0`は常時表示、`1`以上は実績報酬と連動 |
| `title.ja` | string | 日本語の一覧名・詳細見出し |
| `title.en` | string | 英語の一覧名・詳細見出し |
| `pages` | array | ページ定義。配列順が表示順 |

`unlockNo`の同じヒントを複数定義してよい。この場合は1回のアンロックで関連する複数のヒントを同時に表示できる。

### 3.3 ページ

| JSONキー | 型 | 内容 |
|---|---|---|
| `image` | string | 同じフォルダにあるPNGの拡張子を除いたファイル名 |
| `description.ja` | string | 日本語の説明文 |
| `description.en` | string | 英語の説明文 |

たとえば`"image": "how_to_play_01"`は、編集時には`assets/playbook/how_to_play_01.png`、Playdate実行時にはコンパイル済みの`assets/playbook/how_to_play_01`を参照する。サブフォルダ、絶対パス、`..`、拡張子は保存しない。

### 3.4 出力例

```json
{
  "version": 1,
  "playbooks": [
    {
      "id": "how_to_play",
      "unlockNo": 0,
      "title": {
        "ja": "基本の遊び方",
        "en": "HOW TO PLAY"
      },
      "pages": [
        {
          "image": "how_to_play_01",
          "description": {
            "ja": "左右キーで列を選び、下キーでブロックを落とします。",
            "en": "Choose a column with Left or Right, then press Down to drop."
          }
        }
      ]
    }
  ]
}
```

## 4. アンロック連携

- `unlockNo`は実績の配列位置や画面上の表示番号ではなく、PLAYBOOK専用の独立番号とする。
- 実績報酬`reward.type=PLAYBOOK_UNLOCK`の`reward.id`へ、10進数文字列のアンロック番号を設定する。
- 例として`{"type":"PLAYBOOK_UNLOCK","id":"2"}`を取得すると、`unlockNo=2`の全ヒントを表示する。
- 取得済み番号は実績達成状態とは別の永続的な集合として保存する。一度取得した番号は、実績定義やPLAYBOOKの並び順を変更しても失わない。
- `unlockNo=0`は保存対象にせず、報酬IDにも使用しない。
- 未定義の番号を先に取得した場合も番号を保存する。将来その番号を持つヒントが追加されれば表示される。
- Auto Play、リプレイ再生、リプレイから分岐したプレイなど、永続記録対象外のプレイではアンロック番号を付与しない。

## 5. 初期ヒント案

初期データは次の3項目を基準とする。画像名は制作時の推奨名であり、各ページの画像内容が確定した段階でPNGを作成する。

### 5.1 基本の遊び方 / HOW TO PLAY

- ID: `how_to_play`
- Unlock No: `0`

| 画像 | 日本語説明 | English description |
|---|---|---|
| `how_to_play_01` | 左右キーで列を選び、下キーでブロックを落とします。点線のブロックが着地予定位置です。 | Choose a column with Left or Right, then press Down to drop. The dotted tile shows the landing spot. |
| `how_to_play_02` | 落としたブロックが同じ数のブロックに上下左右で触れると、2倍の数へマージします。 | When the dropped tile touches an equal tile vertically or horizontally, they merge into the next value. |
| `how_to_play_03` | 落下とマージの結果によって盤面が90度回転します。回転後にもう一度マージすることもあります。 | Your drop and merges can rotate the board 90 degrees. Another merge may happen after the rotation. |
| `how_to_play_04` | AボタンでブロックをHOLDできます。手を戻したいときはBボタンを長押しします。 | Press A to HOLD a tile. Hold B when you need to rewind the previous move. |

### 5.2 コンボの作り方 / MAKING COMBOS

- ID: `making_combos`
- Unlock No: `1`

| 画像 | 日本語説明 | English description |
|---|---|---|
| `making_combos_01` | 1回のDROP中にマージが続くとコンボになります。次のDROPを始めるとコンボ数は0に戻ります。 | Consecutive merges during one drop form a combo. The combo resets when the next drop begins. |
| `making_combos_02` | 2＋2でできる4の近くに4、その先に8を用意すると、4、8、16へ連続してマージできます。 | Place a 4 beside the result of 2+2, then an 8 beyond it, to chain into 4, 8, and 16. |
| `making_combos_03` | 回転後の位置も考え、できたブロックの移動先に同じ数を置くとコンボを伸ばせます。 | Plan for the rotated position. Put an equal tile where the merged tile will move to extend the combo. |

### 5.3 高い数を作る / BUILDING BIG TILES

- ID: `building_big_tiles`
- Unlock No: `2`

| 画像 | 日本語説明 | English description |
|---|---|---|
| `building_big_tiles_01` | 大きなブロックを1個だけ作るのではなく、次にマージする同じ数のペアを育てます。 | Do not build only one large tile. Grow a matching pair for the next merge. |
| `building_big_tiles_02` | 大きなブロックの周囲に作業場所を残し、小さい数は離れた場所でまとめます。 | Keep working space around large tiles and combine smaller values away from them. |
| `building_big_tiles_03` | NEXTを先まで確認し、今使わない数はHOLDします。回転後に必要な数を置ける形を保ちます。 | Read ahead in NEXT and HOLD values you do not need yet. Preserve a shape that accepts the value needed after rotation. |

アンロック番号`1`と`2`をどの実績報酬へ割り当てるかは、実績達成機能の実装時に決定する。最初から全項目を確認したい開発段階では、一時的に全項目の`unlockNo`を`0`に設定してよい。

## 6. playbook_editor.py

### 6.1 基本動作

- Python 3とTkinterだけで動作し、実行方法は`python3 playbook_editor.py`とする。
- 左側にヒント一覧、右側に選択中ヒントの基本項目とページ一覧・ページ編集フォームを表示する。
- 起動時、前回開いたJSONが存在する場合は自動的に開く。
- 未保存変更がある場合は、ウィンドウタイトルのファイル名直後へ`*`を表示する。
- JSONはUTF-8、インデント2、末尾改行あり、非ASCII文字をエスケープしない形式で保存する。

### 6.2 メニュー

| メニュー | 項目 | 動作 |
|---|---|---|
| File | New | 新しいPLAYBOOK定義を作成する |
| File | Open... | `playbooks.json`を開く |
| File | Save | 現在のファイルへ保存する。未保存ならSave Asを開く |
| File | Save As... | 保存先とファイル名を指定する |
| File | Exit | 未保存変更を確認して終了する |
| Tools | Validate | 保存時と同じ検証を実行する |

ショートカットは新規作成`Ctrl/Cmd-N`、開く`Ctrl/Cmd-O`、保存`Ctrl/Cmd-S`とする。

### 6.3 ヒント一覧と編集項目

一覧は`表示順 / タイトル / Unlock No`を表示する。表示順は配列から自動採番し、JSONへ保存しない。

| 操作 | 動作 |
|---|---|
| Add | 新しいヒントを末尾へ追加する |
| Duplicate | 選択中のヒントと全ページを複製し、重複しない仮IDを付ける |
| Delete | 選択中のヒントを確認後に削除する |
| Up / Down | ヒントを並べ替える |

選択中のヒントでは`ID`、`Unlock No`、`Title JA`、`Title EN`を編集する。

### 6.4 ページ一覧と編集項目

| 操作 | 動作 |
|---|---|
| Add | 選択中ヒントの末尾へページを追加する |
| Duplicate | 選択中ページを複製する |
| Delete | 選択中ページを削除する |
| Up / Down | 同じヒント内でページを並べ替える |

選択中のページでは`Image`、`Description JA`、`Description EN`を編集する。`Browse...`は現在のJSONと同じフォルダを初期位置とし、そのフォルダ直下のPNGだけを選択できる。画像はコピーや変換をせず、拡張子を除いたファイル名だけを保存する。

画像プレビューはTkinterのPNG読み込み機能を使用し、縦横比を維持してプレビュー領域へ収める。ゲームでの原寸表示サイズと、360×128pxを超えていないかを併記する。

## 7. 入力値の検証

保存時と`Tools > Validate`で次を検証する。

- `version`が`1`であること。
- ヒントが1件以上あり、`unlockNo=0`のヒントが1件以上あること。
- `id`が`^[a-z][a-z0-9_]*$`に一致し、重複しないこと。
- `unlockNo`が0以上の整数であること。同じ正数の重複は許可する。
- ヒント名は日本語・英語のどちらか一方が空でないこと。
- 各ヒントにページが1件以上あること。
- `image`が`^[a-z][a-z0-9_]*$`に一致すること。
- JSONと同じフォルダに対応する`.png`が存在し、PNGとして読み込めること。
- 画像が360×128px以内であること。
- 各ページの説明文は日本語・英語のどちらか一方が空でないこと。

エラーはヒント番号、ヒントID、ページ番号、項目名を付けて一覧表示する。エラーがある場合は保存しない。

## 8. 設定ファイル

- 最後に開いたJSONのパスを`仕様書/.playbook_editor_settings.json`へ保存する。
- 設定ファイルが破損している場合、または記録されたファイルが存在しない場合は無視する。
- ファイル選択の初期フォルダは、現在または最後に開いたJSONの親フォルダとする。それがない場合は`playbook_editor.py`と同じフォルダとする。
- 設定ファイル、ウィンドウ位置、プレビュー状態などのエディタ固有情報は`playbooks.json`へ保存しない。
