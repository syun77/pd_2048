# Playdate版 2048回転マージ落ちものパズル 仕様書

> 本書は、現在の`pd_2048/source`の実装を基準にした現行仕様である。仕様変更時は、先に実装と本書の両方を更新する。

## 1. 概要

2048のマージルールをベースにした、5×5盤面の落ちものパズル。中央の回転軸を除く24マスにブロックを配置する。

プレイヤーは左右キーで落下列を選び、下キーで次ブロックを落とす。落下・マージの結果から回転評価値を計算し、評価値が正または負の場合に盤面を時計回りまたは反時計回りへ90度回転する。回転後も、直前に生成されたマージブロックを起点にマージ探索を続ける。

対応画面はPlaydateの400×240px、標準更新レートは30fpsである。

## 2. 基本仕様

| 項目 | 現行仕様 |
|---|---|
| 対応機種 | Playdate |
| 画面解像度 | 400×240px |
| 標準更新レート | 30fps |
| 盤面 | 5×5マス |
| 回転軸 | 中央の`(3,3)`（1始まり） |
| 使用可能マス | 24マス |
| ブロック | 2の累乗の数値ブロック（2、4、8、…） |
| ゲームモード | NORMAL、TIME ATTACK、CORE RUSH、PRACTICE |
| 入力 | 上下左右キー、A、B |
| 通常終了条件 | 合法な落下先が全列でなくなる |
| TIME ATTACK終了条件 | 64 SPRINTは64、256 SPRINTは256、512 SPRINTは512のブロックを作成、または通常のゲームオーバー |
| CORE RUSH勝利条件 | 中央に表示される累積値が2048を超える |

## 3. 盤面と座標

実装の論理座標は左上を`(1,1)`、右下を`(5,5)`とする。

```text
(1,1) (2,1) (3,1) (4,1) (5,1)
(1,2) (2,2) (3,2) (4,2) (5,2)
(1,3) (2,3) (3,3) (4,3) (5,3)
(1,4) (2,4) (3,4) (4,4) (5,4)
(1,5) (2,5) (3,5) (4,5) (5,5)
```

`(3,3)`は全モードで空セルで、ブロックの配置先・回転後の配置先・マージ対象にはならない。CORE RUSHではこのセルにタイルではなく累積値を表示する。

### 3.1 表示位置

盤面は次の設定値で描画する。

| 項目 | 値 |
|---|---:|
| 盤面左上 | x=132、y=54 |
| 1セル | 32×32px |
| 盤面全体 | 160×160px |
| 盤面右下 | x=292、y=214 |
| 回転軸表示 | 中央セルに円を描画 |

セル`(x,y)`の左上は次で求める。

```text
cellX = 132 + (x - 1) * 32
cellY = 54 + (y - 1) * 32
```

## 4. 初期状態とブロック生成

ゲーム開始時は盤面を空にし、回転軸の左右に`8`を固定配置する。

```text
(2,3) = 8
(4,3) = 8
```

初期化時に次ブロックキューを7個生成する。画面上では先頭を除く6個をNEXT欄に表示する。

盤面最大値が16未満の場合は次の確率で生成する。

- `2`：90%
- `4`：10%

盤面最大値が16以上の場合は、`2`から`floor(最大値 / 4)`までの2の累乗を候補とする。通常の重みは`1 / 値`、最大値の4分の1に相当する候補だけは重みを半分にし、正規化して抽選する。

同じ値が3回連続した場合、次の抽選ではその値を候補から除外する。生成値の連続回数はUNDOで復元される。

ブロック生成にはPark–Miller方式のゲーム専用乱数生成器を使用する。通常プレイ開始時にseedを生成し、BGM選択などが使用する`math.random`とは乱数系列を分離する。seedと入力結果を保存したリプレイでは同じ出現列を再現できる。UNDOでは連続値制御に加えて乱数生成器の内部状態も復元する。

## 5. 入力と操作

### 5.1 プレイ中

| 入力 | 動作 |
|---|---|
| 左キー | 落下カーソルを1列左へ移動 |
| 右キー | 落下カーソルを1列右へ移動 |
| 左右キー長押し | 初回300ms後、80ms間隔でカーソルをリピート移動 |
| 下キー | 現在列へ次ブロックを落として手を開始 |
| Aボタン | HOLDを実行 |
| Bボタン長押し | 800ms保持で直前のDROPまたはHOLDをUNDO |
| Bボタン短押し | UNDOしない |

落下カーソルは1〜5列に制限され、初期位置は中央列の`x=3`である。

### 5.2 HOLD

- Aボタンで次ブロックをHOLD欄へ移動する。
- HOLDが空の場合は次ブロックキューを1つ進める。
- HOLD済みの場合は、次ブロック先頭とHOLD中の値を交換する。
- HOLDはDROP前の待機中であれば無制限に使用できる。
- HOLDが空の場合は、選択位置の現在ブロックがHOLDへ移動し、繰り上がったNEXTがNEXT欄から選択列の落下開始位置へ移動する。
- HOLD中のブロックがなく、HOLD後に次ブロックを置けない場合はゲームオーバーになる。
- HOLD実行中は`HOLD_ANIM`アニメーションを再生する。

### 5.3 巻き戻し

- 1手分だけ履歴を保持する（`MAX_UNDO_COUNT=1`）。
- 1ランで3回まで使用できる（`MAX_REWIND_USES=3`）。ゲーム開始・リトライで回数を3に戻す。
- NORMAL、TIME ATTACK、CORE RUSH、PRACTICEの全モードで使用可能。
- TIME ATTACKとCORE RUSHでは、クリアタイム自体は巻き戻さず、実時間を計測する。
- 盤面、スコア、カーソル位置、HOLD、次ブロックキュー、乱数抽選の連続状態をDROP開始前へ戻す。
- HOLD操作自体は1手分のUNDO履歴に含めない。HOLD後にDROPした場合、UNDOするとそのDROP直前のHOLD状態へ戻る。
- 回転を含む手を戻す場合は逆回転アニメーションを再生する。
- HOLD操作自体はUNDO対象ではないため、HOLDの逆方向アニメーションは再生しない。
- ゲームオーバー画面では使用できない。

### 5.4 リプレイ

- リプレイの記録・再生対象はNORMALのみとする。
- 完了したNORMALプレイは、一覧用datastoreの`replayIndex`と、`replay_<ID>`形式の個別datastoreへ分け、新しい順で最大30件保存する。
- `replayIndex`にはID、互換性判定用バージョン、保存日時、お気に入り状態、サマリーだけを保存する。seed、イベント列、最終チェックサムは個別datastoreへ保存し、再生選択時に読み込む。
- 31件目の保存時は最も古いお気に入りでないリプレイを自動削除する。お気に入りは自動削除せず、30件すべてがお気に入りなら新しいリプレイを保存しない。
- リプレイには到達レベル、本体のローカル日時による保存日時、お気に入り状態を含める。
- TIME ATTACK、CORE RUSH、PRACTICEではリプレイを記録せず、保存済みのNORMALリプレイを上書きしない。
- `REPLAY_UNLOCK`報酬を取得済みで、保存済みの互換NORMALリプレイがある場合、タイトルメニューの`REPLAYS`から選択して再生できる。報酬未取得時は項目を表示せず、ゲーム制御側でも再生開始を拒否する。
- 一覧に対応する個別リプレイが欠損、破損または非互換の場合は再生を開始せず、該当項目を一覧から除外する。
- リプレイ一覧では上下で選択し、Aボタンで再生、左右ボタンでお気に入り切替、Bボタンでタイトルへ戻る。お気に入りには`assets/images/fav.png`を表示する。
- 生の左右移動回数は保存せず、各DROP直前の最終列を保存する。
- HOLDは最終状態を再現する最小回数へ圧縮する。HOLDが空でなければ0～1回、空の場合は0～2回になる。HOLD3回は1回として保存する。
- DROPごとにHOLDありまたはHOLDなしのどちらかを1回だけ集計する。
- 操作可能になってから次の確定操作までの待ち時間を保存し、最大3000msとする。アニメーション時間は含めない。
- 成立したREWINDは独立イベントとして保存する。Bボタン長押し入力そのものは再現しない。
- HOLDだけでゲームオーバーになった場合も、DROPなしのターンとして保存する。
- 再生中はAボタンで一時停止し、Bボタンを押している間は各イベントの記録済み待ち時間を省略して早送りする。早送り中も落下・マージ・回転などのアニメーション速度は変えない。それ以外の通常入力は受け付けない。画面左下に現在手数と総手数を`REPLAY 10/32`の形式で表示する。一時停止中は左ボタンで1手前、右ボタンで1手後の終了状態へ移動でき、Bボタンで選択地点から再生を再開する。Bボタンを押し続けた場合はそのまま早送りする。1手目での左と最終状態での右は何も行わない。手送りで最終結果へ到達した場合は結果画面への遷移を保留し、A/Bボタンで遷移する。手数は`TURN`イベントだけを数え、`REWIND`と`CHECKPOINT`は前の手に含めて再現するが手数には含めない。
- `EXTEND_PLAY`報酬を取得済みの場合だけ、一時停止中に`A: PLAY FROM HERE`を表示する。Aボタンを押すと「プレイを再開する？」という`YES`／`NO`ダイアログを表示する。初期選択は`NO`とし、上下で選択、Aで決定、Bでキャンセルする。`YES`では表示中のゲーム状態をそのままプレイヤー操作へ引き継ぎ、`NO`またはBでは同じ地点の一時停止へ戻る。報酬未取得時、最終結果へ到達済みの場合、再生エラー後は分岐できない。
- 分岐時は盤面、NEXT、HOLD、カーソル、スコア、レベル、乱数状態、残りREWIND回数、UNDO、進行中アニメーションを保持する。未適用のリプレイイベントは破棄し、すでに受理した操作とアニメーションは取り消さない。アニメーション途中なら通常速度で完了した後に操作可能となる。
- リプレイから分岐したプレイではスコアやレベルなどのラン内進行は通常どおり行うが、リプレイ、ハイスコア、最高レベル、累計統計、NORMAL履歴、中断データ、実績達成と報酬は一切保存しない。結果画面では新記録表示を行わない。`Retry`は新しい記録対象のNORMALを開始する。
- 再生終了時に盤面、NEXT、HOLD、スコア、乱数状態などのチェックサムを検証する。
- 再生中はハイスコアと最高レベルを更新しない。
- 待ち時間を3秒へ切り詰めるため、再生中の経過時間は元プレイと一致しない場合がある。元プレイの経過時間はリプレイのサマリーへ保存する。

### 5.5 中断セーブ

- 中断セーブは記録対象のNORMALをプレイヤーが操作している場合だけ使用でき、TIME ATTACK、CORE RUSH、PRACTICE、リプレイ再生、リプレイから分岐したプレイ、ゲームオーバーでは使用できない。
- 中断データはdatastoreの`normalSuspend`へ1件だけ保存し、リプレイ一覧の最大30件には含めない。再度中断した場合は最新データで上書きする。
- NORMALプレイ中のPlaydateシステムメニューでは`Back to Title`の代わりに`Suspend`を表示する。保存に成功した場合だけタイトルへ戻り、失敗した場合はゲームを継続して`SUSPEND FAILED`を表示する。
- 互換性のある中断データが存在する場合、タイトルの`NORMAL GAME`から`CONTINUE`と`NEW GAME`を選択する。初期カーソルは`CONTINUE`とし、Bボタンでタイトルへ戻る。
- `CONTINUE`はseedと論理イベント列から状態を高速復元し、チェックサムが一致した場合だけ通常入力とリプレイ記録を再開する。復元中はゲーム画面を描画せず、`NOW LOADING...`だけを表示して、待ち時間、SE、各アニメーションの実時間を省略する。
- `NEW GAME`は中断データを破棄して新しいNORMALを開始する。復元成功時にも中断データを削除するため、中断データは一回だけ使用できる。
- 中断前後の論理イベント列は引き継ぎ、ゲーム終了時に保存する完成リプレイへ両方を含める。
- 中断時点の未確定なカーソル移動とHOLD結果は`CHECKPOINT`イベントとして保存する。アニメーション中に中断した場合、受理済み操作を次の安定した`INPUT`状態まで適用した状態を中断地点とする。
- アニメーションの途中フレーム、一時メッセージ、キーの押下状態、BGMとSEの再生位置は復元しない。
- 中断データの欠損、非互換、復元後のチェックサム不一致では通常プレイを開始せず、タイトルへ戻って`SUSPEND DATA ERROR`を表示する。失敗した中断データは自動削除しない。
- プレイヤー操作中のNORMALからシステムメニューでホームへ戻る場合は、`playdate.gameWillTerminate()`で同じ中断データを自動保存する。
- プレイヤー操作中のNORMALで低バッテリースリープへ入る場合は、`playdate.deviceWillSleep()`で同じ中断データを自動保存する。通常の端末ロックでは保存しない。
- 自動保存ではタイトルへ遷移せず、通知やSEを再生しない。タイトル、他モード、リプレイ再生、復元処理中、ゲームオーバーでは保存しない。
- 自動保存後にプレイを継続してゲームオーバー、リトライまたは新規NORMAL開始となった場合は、古い中断データを削除する。

## 6. 落下可能セル

`findDropCell`は各列を`y=1`から`y=5`へ調べ、最初に見つかった合法セルを落下先とする。落下先より上側にブロックがある場合は、その列に落下できない。下側のブロックは接着面として利用できる。

セルが次のいずれかを満たす場合に落下先となる。

1. 下隣セルにブロックがある。
2. 左隣または右隣セルにブロックがある。
3. 中央列の`(3,2)`である（中央の回転軸`(3,3)`を飛び越えるための特例）。

盤面下端そのものを特別扱いしていないため、空の列の最下段へ自由落下するルールではない。接着面が存在する列だけが合法な落下列になる。

中央の回転軸セルは接着面としても使用しない。ただし、中央列の`(3,2)`だけは上記特例で配置できる。

## 7. 1手の解決順序

```text
入力受付
  ↓
現在列の合法な落下先を検索
  ↓
DROP履歴を保存、落下アニメーション
  ↓
ブロックを盤面へ確定
  ↓
落下位置を回転評価へ加算
  ↓
落下ブロックを起点にマージ探索
  ↓
マージがあればマージアニメーション・盤面更新・スコア加算
  ↓
マージがなくなるまで同じ起点で探索
  ↓
回転評価が0なら回転せず終了
  ↓
評価が正なら時計回り、負なら反時計回りに90度回転
  ↓
回転後のアクティブブロックを起点にマージ探索
  ↓
マージがなくなるまで探索
  ↓
次ブロックキューを進め、NEXTアニメーション
  ↓
次ブロックをどの列にも置けなければゲームオーバー
```

盤面回転後に、全ブロックを下方向へ詰める重力処理は実装していない。`applyGravity`は中央セルを空に保つ処理のみである。

処理中は入力を受け付けない。落下、マージ、回転、NEXT、HOLDの各アニメーション完了後に次の処理へ進む。

## 8. 回転ルール

回転方向は落下列だけで固定されない。落下位置とマージ方向から回転評価値を計算する。

- 落下位置は、中央列より左なら負、右なら正、中央なら0を加算する。
- マージ元・マージ先の左右関係や位置も評価値へ加算する。
- 評価値は`-200〜200`の範囲に制限される。
- 評価値が正：時計回りに90度。
- 評価値が負：反時計回りに90度。
- 評価値が0：回転なし。

したがって、中央列への落下でもマージ結果によって回転する場合がある。

5×5盤面の座標変換は次のとおり（実装は1始まり）。

時計回り：

```text
newX = 6 - oldY
newY = oldX
```

反時計回り：

```text
newX = oldY
newY = 6 - oldX
```

回転軸`(3,3)`は回転後も空セルとして保持する。

## 9. マージルール

- 上下左右に隣接する同じ値のブロックを1組ずつマージする。
- マージ結果は同値の2倍になる。
- マージ元は消え、マージ先が結果値になる。
- 1回の手で、生成されたマージブロックを起点に連続マージを行う。
- 同じマージ処理中に、同じブロックを別の組み合わせで再度マージすることはない。
- 回転軸セルを経由した隣接は成立しない。
- マージ先は、可能な限り周囲のブロックとの接続を維持する候補を優先する。
- 複数候補の評価では、位置・マージ方向などを使って回転評価値も更新する。
- 候補探索の基本方向は下、左、右、上の順である。

マージ中は元ブロックがマージ先へ移動する`MERGING`アニメーションを再生し、完了時に盤面を更新する。

## 10. スコアとコンボ

通常のマージ加点は、生成されたマージ結果の値にスコア倍率100を掛けた値である。

```text
2 + 2 = 4   → +400点
4 + 4 = 8   → +800点
8 + 8 = 16  → +1600点
```

同一手内のマージ回数をコンボとして記録する。2コンボ目以降は、次の差分を追加加点する。

```text
bonus = floor(2 * combo^1.5 - 2 * (combo - 1)^1.5)
実際の加点 = bonus * 100
```

新しいDROPを開始するとコンボは0へ戻る。コンボが2以上になると、コンボ表示とコンボSEを再生する。

NORMALはスコアと最高到達レベル、TIME ATTACKとCORE RUSHは種目別のハイスコアとクリアタイムを記録する。累計統計はバージョン付きの`statistics`へ保存し、NORMALの従来記録キー`highScore`と`normalBestLevel`、CORE RUSHの従来記録キー`coreRushBestTimeMs`から初回読み込み時に移行する。64、256、512 SPRINTとCORE RUSHのハイスコアは種目別に保存し、既存の統計データで欠落している場合は0とする。64、256、512 SPRINTのベストタイムは種目別に保存し、短い記録をベストとする。種目を判別できない従来の`timeAttackBestTimeMs`は種目別ベストへ移行しない。

### 10.1 NORMALレベル

NORMALでは1プレイ中の成果をまとめた進捗指標としてレベルを使用する。ゲーム開始時はレベル1、累計XP 0とし、レベルによるルール・難易度・ブロック出現内容の変更は行わない。他モードではレベルを加算・表示しない。

XPは次のタイミングで加算する。

- 合法なDROPが盤面へ確定したときに1 XP。初期配置、NEXT抽選、HOLD、失敗したDROPは対象外。
- マージごとに`max(1, ceil(log2(マージ後の値) / 2))` XP。
- 同じプレイ中にマージで16以上の指定値を初めて作成したとき、次の初到達ボーナス。同じ値の2回目以降とランダム生成値は対象外。

| マージ後の値 | 初到達ボーナスXP |
|---:|---:|
| 16 | 5 |
| 32 | 10 |
| 64 | 20 |
| 128 | 35 |
| 256 | 55 |
| 512 | 80 |
| 1024 | 110 |
| 2048 | 150 |

1手のマージ探索と回転後のマージがすべて終了した時点で、最終コンボ数が2以上なら`(コンボ数 - 1)^2` XPを加算する。複数種類のXPが同じ手で成立した場合はすべて加算する。

現在レベルから次のレベルまでの必要XPは次の式とする。余剰XPは次のレベルへ持ち越し、一度の加算で複数レベル上昇できる。レベル上限は設けない。

```text
次のレベルまでの必要XP = 20 + 5 × (現在レベル - 1)
```

レベルアップ時はゲーム進行を止めずに`LEVEL UP`と到達レベルを一時表示する。ゲーム画面には現在レベル、現在レベル内のXP、次レベルまでの必要XP、進捗ゲージを表示する。結果画面には最終レベルをスコアと併記し、最高レベルを更新したプレイでは`NEW BEST LEVEL`を表示する。STATISTICSにはNORMALの最高レベルを表示する。

REWINDではレベル、累計XP、DROP数、XP内訳、初到達済みの値をDROP開始前へ戻す。すでに保存した歴代最高レベルは戻さない。Auto Playを一度でも有効にしたプレイはレベル自体を計算・表示するが、歴代最高レベルの保存対象外とする。

実績定義では`LEVEL`、`scope=RUN`、`params.value`をNORMALの到達レベル条件として使用できる。達成判定の責務と判定タイミングは`仕様書/実績システム設計.md`に従う。

### 10.2 TIME ATTACK

- タイトルの`TIME ATTACK`サブメニューから`64 SPRINT`を選択する。
- 通常ルールでゲームを開始し、64のブロックを作成するまでの経過時間を競う。
- 制限時間は設けない。
- 64のブロック作成後に勝利し、クリアタイムを保存する。
- タイトルの`TIME ATTACK`サブメニューから`256 SPRINT`を選択する。
- 128のブロックを左右（`(2,3)`と`(4,3)`）に初期配置し、256のブロックを作成するまでの経過時間を競う。
- 制限時間は設けず、画面上部には残り時間ではなく経過時間を表示する。
- 256のブロック作成後に勝利し、64 SPRINTと同じクリアタイム記録を使用する。
- タイトルの`TIME ATTACK`サブメニューから`512 SPRINT`を選択する。
- 256のブロックを左右（`(2,3)`と`(4,3)`）に初期配置し、512のブロックを作成するまでの経過時間を競う。
- 制限時間は設けず、画面上部には経過時間を表示する。512のブロック作成後に勝利し、64 SPRINT・256 SPRINTと同じクリアタイム記録を使用する。

### 10.3 CORE RUSH

- タイトルの`TIME ATTACK`サブメニューから選択する。
- 初期盤面はブロックを配置せず、中央`(3,3)`に累積値`0`を表示する。
- 各マージ完了時に`マージ後の値 × コンボ数`を累積値へ加算する。
- 加算時に画面中央へ次の2行を一時表示する。
  - `[コンボ数] COMBO`
  - `[マージ後の値] x [コンボ数] = [加算値]`
- ゲーム開始からクリアまでの経過時間を計測する。制限時間は設けない。
- 累積値が`2048`を超えた時点で勝利し、勝利判定をゲームオーバー判定より優先する。
- 累積値はREWINDで巻き戻す。

### 11.1 タイトルメニュー

TIME ATTACKサブメニューの画面最下部には、選択中の64・256・512 SPRINTまたはCORE RUSHに対応する種目別ハイスコアとベストタイムを横並びで表示する。左側は`HIGH SCORE N`、右側は`BEST TIME MM:SS.CC`の形式とし、ベストタイム未記録の場合は`BEST TIME --:--.--`と表示する。

1. `NORMAL GAME`
2. `TIME ATTACK`
3. `PRACTICE`
4. `PLAYBOOK`
5. `ACHIEVEMENTS`
6. `STATISTICS`

タイトル画面のROOTメニューから`PRACTICE`を選択できる。PRACTICEを選択すると、`assets/practice`内の連番JSONステージ一覧を読み込む。各ステージの`label`をメニュー項目として表示し、クリア済みステージは`assets/images/check.png`を付けて表示する。選択中ステージの英語説明文を画面下部に表示する。決定後は、選択したJSONの盤面・NEXT・クリア目標・説明文を使用する。ステージをクリアしたかどうかはステージIDごとにPlaydateの`datastore`へ保存する。

PRACTICEなどのサブメニューで項目数が5件を超える場合は、上下キーの選択移動に合わせてメニューをスクロールし、選択中の項目が可能な限りメニュー中央に表示される。1画面に表示する項目数は5件とし、5件以下の場合はスクロールせず全項目を表示する。上側に画面外の項目がある場合は`▲`、下側に画面外の項目がある場合は`▼`を表示する。また、項目の右端に縦スクロールバーを表示し、つまみの位置で項目のオフセット、つまみの高さで全項目に対する表示項目数の割合を示す。

タイトル画面、TIME ATTACK/PRACTICEサブメニュー、PLAYBOOK画面、ACHIEVEMENTS画面、STATISTICS画面、SOUND TEST画面では、`MENU_BACKGROUND_LOAD`が`LOW`、`MEDIUM`、`HIGH`のときに1-bit向けの幾何学模様アニメーションを背景へ重ねる。背景はキャッシュ用イメージへ一定間隔で再描画し、毎フレームの計算量を抑える。`LOW`、`MEDIUM`、`HIGH`の順にモアレ円の描画密度と更新頻度が上がり、`HIGH`ではリサージュ線も描画する。初期値は`OFF`である。`SHOW_MENU_BACKGROUND_MENU_ITEM`が`true`の場合だけ、対象画面のPlaydateシステムメニューに`BG: ...`を追加し、`OFF`、`LOW`、`MEDIUM`、`HIGH`を実行中に切り替えられる。現行設定は`false`のため、この項目は表示しない。

タイトル画面でPlaydateシステムメニューを開いた場合だけ、オプション項目`language`を表示する。選択肢は`en`と`ja`で、変更した言語は`datastore`へ保存する。保存値がない初回起動時はPlaydate OSが日本語なら`ja`、それ以外なら`en`を使用する。この設定はPLAYBOOKとACHIEVEMENTSの見出し、本文、空表示、各画面から戻るシステムメニュー項目へ反映する。`ja`選択時のPLAYBOOKとACHIEVEMENTSのゲーム内描画には`assets/fonts/k8x12`を使用する。タイトル、ゲーム、ゲームオーバー、STATISTICS、SOUND TESTなど、それ以外の画面は言語設定にかかわらずPlaydateのデフォルトフォントを使用する。

- 初期盤面は`(2,3)=8`、`(4,3)=8`。
- NEXTの生成列は`2, 2, 4, 8`で、末尾まで進むと先頭へ戻る。
- 盤面、マージ、回転、HOLD、UNDO、ゲームオーバー判定は通常ルールを使用する。
- タイマー、ハイスコア保存、TIME UP、CORE RUSH勝利判定は使用しない。
- シナリオの`objectives`でクリア目標を設定できる。
- シナリオの`description`で1行程度の説明文を設定できる。`description.ja`に日本語、`description.en`に英語を指定でき、システム言語が日本語なら日本語、それ以外なら英語を優先してゲーム画面に表示する。優先言語が空の場合はもう一方へフォールバックする。
- `TILE_VALUE`は指定値以上のブロック作成、`COMBO`は指定コンボ数、`SCORE`は指定スコア、`MERGE_COUNT`は指定マージ回数を目標とする。
- 複数目標は`objectiveMode`が`ANY`ならいずれか、`ALL`ならすべて達成した時点でクリアする。
- `turnLimit`が1以上の場合、指定手数に達してもクリア条件を満たしていなければ失敗（ゲームオーバー）とする。クリア条件の達成は失敗より優先する。
- `turnLimit`が1以上の場合、出現ブロック数は指定手数までとする。NEXTが空になった後にHOLDブロックが残っていれば、それを次の操作対象とし、NEXTがない状態ではHOLDを使用できない。

実績エディタが扱う定義データは`pd_2048/source/assets/achievement/achievements.json`に保存し、全18件の条件、表示文言、報酬、表示順を保持する。編集データの詳細は`仕様書/実績エディター.md`に従う。アプリケーション側の読込、達成判定、達成状態と報酬の永続保存、機能解放、達成通知は`仕様書/実績システム設計.md`の設計に従って実装する。

実績を新規達成した場合は、全シーンの描画より前面となる画面上部へ`ACHIEVEMENT UNLOCKED`、実績のNo、英語名を3秒間表示する。同時に複数達成した場合も一度に表示する通知は1件だけとし、1件の表示終了後に次の通知をJSON配列順で連続表示する。通知は入力を遮断せず、シーン遷移でも破棄しない。

PLAYBOOK画面は`assets/playbook/playbooks.json`に定義された解放済みヒントを配列順に一覧表示する。上下キーで選択し、Aボタンで複数ページのヒント詳細を開く。詳細では画面中央に説明画像、画面下部にタイトルの`language`で選択した言語の説明文を表示し、左右キーでページを切り替え、Bボタンで一覧へ戻る。一覧ではBボタンでタイトルへ戻る。`unlockNo=0`は常時表示し、`unlockNo>=1`は同じ番号のPLAYBOOKアンロック報酬を取得した場合に表示する。JSON形式、初期ヒント案、画像制約、アンロック連携、実装済みの`仕様書/playbook_editor.py`の仕様は`仕様書/プレイブックエディター.md`に従う。現行アプリケーションは一覧・詳細表示、実績達成によるアンロック番号の永続保存、保存済み番号による表示制御を実装済みである。

ACHIEVEMENTS画面は全実績をJSON配列順に一覧表示する。各行にNoと選択言語の実績名を表示し、達成済みの行は左端に`assets/images/check.png`を表示する。選択項目の説明文は画面下部へ表示する。`progressVisible=true`の未達成実績は説明文へ現在値／目標値を付記し、`hidden=true`の未達成実績は名前と説明を隠す。上下キーで循環選択し、5件を超える場合はスクロールする。Bボタンまたは言語に対応するシステムメニュー項目でタイトルへ戻る。

完成仕様では、NORMAL、PRACTICE、PLAYBOOK、ACHIEVEMENTS、STATISTICSを常時選択可能とし、次の機能は実績報酬で解放する。TIME ATTACKルート項目は解放済みの対象モードが1件以上ある場合に表示し、サブメニューには解放済みモードだけを表示する。

| 機能 | 解放条件 |
|---|---|
| 64 SPRINT | NORMALで64以上のタイルを作成 |
| 256 SPRINT | NORMALで256以上のタイルを作成 |
| 512 SPRINT | NORMALで512以上のタイルを作成 |

全報酬の解放状態はdatastoreの`achievements.rewards`へ種別ごとに保存する。タイトルには解放済みのTIME ATTACKモードだけを表示し、REPLAYSは権利と保存データの両方がある場合だけ、SOUND TESTは権利がある場合だけ表示する。リプレイ分岐とPLAYBOOKも保存済み権利を利用時に検査する。新規データでは全対象機能を未解放とし、実績達成と同じdatastore書込みで対応する報酬を解放する。

STATISTICS画面は左右入力で次の3ページを切り替える。統計項目を囲む白い矩形の左右端から内側8pxには、`fillPolygon`で描画した白縁取り・黒塗りの三角形ページ切り替えカーソルを表示する。入力した方向のカーソルは、メニューの上下スクロールカーソルと同様に一時的に外側へ移動してから定位置へ戻す。

| ページ | 表示項目 |
|---|---|
| OVERALL | 項目名を左揃え、値を右揃えの固定した個別のX座標へ描画し、全モードのプレイ時間、NORMAL・各SPRINT・CORE RUSHの合計プレイ回数、PRACTICEクリア数／全ステージ数を表示する |
| NORMAL | 項目名を左揃え、値を右揃えの固定した個別のX座標へ描画し、プレイ回数、最高スコア、最高レベル、マージで生成した最高ブロック値、最大コンボ数を表示する |
| TIME ATTACK | `MODE`、`SCORE`、`TIME`、`CLEAR`を固定した個別のX座標へ描画し、64・256・512 SPRINTとCORE RUSHそれぞれのハイスコア、ベストタイム、クリア回数／プレイ回数を列表示する |

NORMALページではAボタンで通常統計と履歴グラフを切り替える。通常統計では画面下部に`A: GRAPH`、履歴グラフでは`A: SUMMARY`を表示する。履歴グラフを表示した状態で左右入力した場合は、履歴グラフを閉じて隣のカテゴリへ移動する。Bボタンはいずれの表示でもタイトルへ戻る。

NORMALの履歴は、統計対象としてゲームオーバーまで完了したプレイについて、最終到達レベルと最終スコアを古い順に最大30件保存する。31件目を追加すると最古の1件を削除する。中断保存からCONTINUEした場合は同じプレイとして扱い、ゲームオーバー時に1件だけ記録する。ゲームオーバー前にRetryまたはタイトルへ戻ったプレイ、PRACTICE、TIME ATTACK、CORE RUSH、リプレイ再生、リプレイから分岐したプレイ、Auto Playを一度でも有効にしたプレイは履歴へ記録しない。REWINDを使用した場合はゲームオーバー時点のレベルとスコアを記録する。

履歴グラフは横軸を統計対象として完了したNORMALプレイ番号、縦軸を到達レベルとする折れ線グラフで、左から右へ古い順に配置する。各プレイを黒い点で描画し、隣接する点を黒線で接続する。横軸の左右端には表示中の最古と最新のプレイ番号を表示する。縦軸は0を下端とし、履歴内の最高レベルを5単位で切り上げた値を上端とする。ただし上端の最低値は5とする。履歴が1件の場合は中央に点だけを表示し、履歴がない場合は`NO PLAY HISTORY`を表示する。

グラフ下部には、表示対象となる直近最大30件から算出した`AVG LEVEL`と`AVG SCORE`を表示する。項目名は左揃え、値は右揃えで個別に描画する。平均レベルは小数第1位、平均スコアは四捨五入した整数とし、履歴がない場合は`--`を表示する。これは生涯平均ではなく、保存されている履歴だけの平均とする。

統計保存形式はバージョン3とし、`normal.history.completedPlays`に記録対象として完了した通算プレイ数、`normal.history.runs`に最大30件の`number`、`level`、`score`、`timeAttack`の各種目に`highScore`を保存する。バージョン1以前の統計から最高スコアなどの既存値は引き継ぐが、過去のレベルとスコアの組み合わせは復元せず、履歴はアップデート後に完了したプレイから開始する。バージョン2以前にTIME ATTACKとCORE RUSHのハイスコアは存在しないため0から開始する。

統計上のプレイ回数は、対象モードで最初の合法なDROPを開始した時点で1回加算する。ゲーム画面へ入っただけの場合、PRACTICE、リプレイ再生は合計プレイ回数へ含めない。中断したNORMALをCONTINUEした場合は同じプレイとして扱い、再加算しない。TIME ATTACKとCORE RUSHのクリア回数は、1回以上DROPしたプレイで勝利が確定した時点で加算する。

プレイ時間は、GET READY終了後にゲーム画面でプレイヤーが操作・思考している時間と、落下・マージ・回転などのアニメーション時間を全モードで加算する。タイトル・結果・システムメニュー・スリープ・リプレイ再生・Auto Play動作中の時間は含めない。長いフレーム間隔はシステムメニューまたはスリープとして除外する。

NORMALの最高ブロック値は初期配置やランダム出現値ではなく、マージで生成した値だけを対象とする。最大コンボと最高ブロック値はREWIND後も達成済み記録として残す。Auto Playを一度でも有効にしたプレイは、プレイ回数、クリア回数、ベストタイム、TIME ATTACK・CORE RUSHのハイスコア、NORMALの最高スコア・最高レベル・最高ブロック値・最大コンボ数の記録対象外とする。リプレイ再生とリプレイから分岐したプレイも同様に全記録の対象外とする。

ブロック出現総数、マージ総数、DROP総数、HOLD・回転・REWIND使用回数、生涯累計スコアは保存・表示せず、実績用の内部カウンターも持たない。

SOUND TEST画面はBGMとSEの試聴画面である。左右キーで`BGM`と`SE`を切り替え、上下キーで項目を選択し、Aボタンで選択中のBGMまたはSEを再生する。Bボタンで再生中のBGMを停止してタイトル画面へ戻る。BGMの再生が終了すると次のBGMを自動選択して再生する。BGM再生時は`assets/bgm_db`内の同名JSONを再生中の1曲分だけ読み込み、再生位置、再生進捗、低域・中域・高域の概算レベルを画面右下の3本の縦棒で表示する。JSONが単一レベル列だけを持つ場合は中域として表示する。

## 13. ゲームオーバー判定

次のいずれかを満たした場合にゲームオーバーとする。

1. 次ブロックを5列のどの列にも合法的に配置できない。
2. HOLD実行後、次ブロックを5列のどの列にも合法的に配置できない。

盤面の見た目が満杯でなくても、接着条件を満たす落下先がなければゲームオーバーとなる。逆に、マージや配置によって合法な落下先が生じれば継続できる。

TIME ATTACKとCORE RUSHではゲーム開始からの経過時間を計測する。勝利条件を満たしたマージのアニメーション完了後に勝利表示へ遷移し、ポーズ状態ではタイマーを進めない実装だが、通常のゲーム画面からPAUSEDへ入る操作は未実装である。

## 14. システムメニューと補助機能

タイトル画面のメニューカーソルはページごとに保持する。TIME ATTACKまたはPRACTICEのサブメニューからBボタンで戻った場合、ルートメニューでは遷移元の`TIME ATTACK`または`PRACTICE`にカーソルを置く。ルートメニューからAボタンでTIME ATTACKまたはPRACTICEへ進んだ場合、サブメニューのカーソルは先頭項目に置く。ゲーム中または結果画面の`Mode Select`、`Stage Select`から戻った場合は、直前に選択して開始したTIME ATTACKモードまたはPRACTICEステージにカーソルを置く。

Playdateのシステムメニュー項目は画面遷移時に切り替える。

| 画面 | 項目 |
|---|---|
| タイトルのルート（モード選択） | `language`（`en` / `ja`）、`Reset Save Data`。`SHOW_MENU_BACKGROUND_MENU_ITEM`が`true`の場合のみ`BG: ...` |
| タイトルのサブメニュー | `language`（`en` / `ja`）。`SHOW_MENU_BACKGROUND_MENU_ITEM`が`true`の場合のみ`BG: ...` |
| ゲーム（NORMAL GAME） | `Suspend`、`Retry`。`SHOW_AUTO_PLAY_MENU_ITEM`が`true`の場合のみ`Auto Play`。リプレイ再生中とリプレイから分岐したプレイ中は`Suspend`ではなく`Back to Title` |
| ゲーム（TIME ATTACK） | `Mode Select`、`Retry`。`SHOW_AUTO_PLAY_MENU_ITEM`が`true`の場合のみ`Auto Play` |
| ゲーム（PRACTICE） | `Stage Select`、`Retry`。`SHOW_AUTO_PLAY_MENU_ITEM`が`true`の場合のみ`Auto Play` |
| ゲームオーバー | 現在のモードに応じた戻り項目（`Back to Title`、`Mode Select`、`Stage Select`）と`Retry` |
| PLAYBOOK一覧 | `en`では`Back to Title`、`ja`では`タイトルへ`。`SHOW_MENU_BACKGROUND_MENU_ITEM`が`true`の場合のみ`BG: ...` |
| PLAYBOOKヒント詳細 | `en`では`Back to Playbook`、`ja`では`プレイブックへ`。`SHOW_MENU_BACKGROUND_MENU_ITEM`が`true`の場合のみ`BG: ...` |
| ACHIEVEMENTS | `en`では`Back to Title`、`ja`では`タイトルへ`。`SHOW_MENU_BACKGROUND_MENU_ITEM`が`true`の場合のみ`BG: ...` |
| STATISTICS、SOUND TEST | `Back to Title`。`SHOW_MENU_BACKGROUND_MENU_ITEM`が`true`の場合のみ`BG: ...` |

- `Auto Play`：自動プレイの有効・無効を切り替える開発・補助機能。`SHOW_AUTO_PLAY_MENU_ITEM`が`true`の場合だけ表示する。現行設定では`DEBUG_FLAG=true`から`SHOW_AUTO_PLAY_MENU_ITEM=true`となるため表示する
- `Back to Title`：タイトルへ戻る
- `Back to Playbook`：PLAYBOOKのヒント一覧へ戻る
- `Suspend`：現在のNORMALを中断保存し、保存成功後にタイトルへ戻る
- `Mode Select`：TIME ATTACKのモード選択へ戻る
- `Stage Select`：PRACTICEのステージ選択へ戻る
- `Retry`：現在のモードでリスタート
- `language`：PLAYBOOKとACHIEVEMENTSの表示言語を`en`または`ja`から選択する
- `Reset Save Data`：ゲーム内の`RESET SAVE DATA?`確認画面を開く。初期選択は`NO`とし、`YES`を確定した場合だけ、言語設定、ハイスコア、レベル記録、PRACTICE進捗、統計、実績と報酬、中断データ、保存済みリプレイを削除してゲームを再起動する。`NO`の確定またはBボタンでキャンセルする
- `BG: ...`：メニュー背景アニメーションの負荷設定を`OFF`、`LOW`、`MEDIUM`、`HIGH`の順に切り替える

Auto Playは通常の入力と同じDROP、HOLD、左右移動コマンドをゲームコントローラへ渡す。

`DEBUG_FLAG=true`の場合はAuto Playに加えてFPSも画面左上へ表示する。現行設定は`true`である。

## 15. 実装上の不変条件

- 盤面配列は5×5、空セルは`0`で保持する。
- `(3,3)`は常に`0`である。
- 盤面の回転・マージ・履歴管理は描画処理から分離する。
- アニメーション中は新しいゲーム操作を受け付けない。
- NEXTキューは内部に7個保持し、表示は6個とする。
- ハイスコア、NORMALの最高レベル、PRACTICEステージのクリア状況、NORMALの中断データはPlaydateの`datastore`へ保存する。
